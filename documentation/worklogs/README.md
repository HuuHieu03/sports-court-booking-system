# Worklog của team

Mỗi thành viên ghi ngắn công việc mình thực hiện, kết quả kiểm tra và việc còn vướng. Có thể cập nhật cùng một file trong ngày cho cùng công việc.

Đặt tên file theo dạng `YYYY-MM-DD-ten-thanh-vien-noi-dung.md` để tránh trùng giữa các thành viên. Ghi tên người thực hiện và nhánh hoặc commit liên quan nếu có.

## Nội dung một bản ghi

```markdown
# Công việc

Ngày: YYYY-MM-DD
Người thực hiện:
Nhánh hoặc commit:

## Đã làm

Ghi phần đã hoàn thành và những file hoặc chức năng chính bị ảnh hưởng.

## Kiểm tra

Ghi lệnh hoặc cách kiểm tra cùng kết quả thực tế. Nếu chưa kiểm tra, ghi rõ.

## Vướng mắc và việc tiếp theo

Ghi vấn đề còn tồn tại, quyết định cần trao đổi và bước tiếp theo.
```

Worklog ghi tiến độ thực tế. Thay đổi nghiệp vụ cần cập nhật [PRD](../product/PRD.md), thay đổi thiết kế cần cập nhật [kiến trúc](../architecture/ARCHITECTURE.md), thay đổi API cần cập nhật [OpenAPI](../api/openapi.yaml).

Các lỗi baseline được ghi là lỗi chủ đích. Khi đo hoặc cải tiến, ghi bản baseline, bản cải tiến, môi trường và kết quả để người khác tái hiện. Chỉ đưa nội dung phục vụ công việc chung vào đây.
